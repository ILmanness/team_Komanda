# Корпоративная крыса — арена переговоров

Веб-игра для тренировки рабочих переговоров. В проекте есть сюжетные разговоры, тренировки с подготовленными ответами, база знаний, личный кабинет и редактор материалов для администратора.

Ниже описан локальный запуск на вашем компьютере. Все команды выполняйте из папки проекта, в которой находится `compose.yaml`.

## Что понадобится

- Git для скачивания проекта.
- Запущенный Docker с поддержкой Compose v2. На Windows и macOS подойдёт Docker Desktop.
- Доступ к интернету при первом запуске для загрузки образов и зависимостей.

Python, Node.js и PostgreSQL отдельно устанавливать не нужно. Команда `docker version` должна показывать разделы `Client` и `Server`.

## 1. Скачать проект

~~~sh
git clone --branch main https://github.com/ILmanness/team_Komanda.git
cd team_Komanda
~~~

Если проект уже скачан, перейдите в его папку. Обновление существующей установки описано ниже.

## 2. Создать файл настроек

Скопируйте `.env.example` в `.env`. Если `.env` уже существует, повторно копировать пример не нужно.

В PowerShell:

~~~powershell
Copy-Item .env.example .env
~~~

В Linux, macOS или Git Bash:

~~~sh
cp .env.example .env
~~~

Откройте `.env` и до первого запуска задайте:

| Переменная | Что указать |
|---|---|
| `POSTGRES_PASSWORD` | Придумайте пароль для базы данных. |
| `ADMIN_BOOTSTRAP_PASSWORD` | Придумайте пароль учётной записи `admin` для входа в редактор. |
| `AUTH_SECRET_KEY` | Случайную строку для защиты сеансов входа. |

Для генерации `AUTH_SECRET_KEY` выполните команду и вставьте результат в `.env`:

~~~sh
docker compose run --rm --build --no-deps migrate python -c "import secrets; print(secrets.token_hex(32))"
~~~

Пароль администратора и пароль базы данных — разные значения. Не публикуйте `.env`: в нём хранятся пароли и, если подключена модель, её ключ. Файл уже исключён из Git.

Остальные параметры можно оставить как в примере. Если порты `5173`, `8000` или `5432` заняты, измените соответственно `FRONTEND_PORT`, `BACKEND_PORT` или `DB_PORT` в `.env`.

## 3. Запустить игру

~~~sh
docker compose config --quiet
docker compose up --build -d
docker compose ps -a
~~~

Если первая команда завершилась без ошибки, настройки Compose корректны. Первый запуск может занять несколько минут. Повторяйте `docker compose ps -a`, пока `db`, `backend` и `frontend` не станут `healthy`.

Контейнеры `migrate`, `content-import`, `demo-seed` и `admin-bootstrap` выполняют разовую подготовку и завершаются. Для них статус `Exited (0)` означает успешную работу. При другом коде посмотрите сообщения командой `docker compose logs --tail=100 <имя-сервиса>`.

При первом запуске автоматически появляются 4 темы, 29 материалов и 4 теста базы знаний, 9 методов и 8 принципов тренировки (по два сценария у каждого инструмента), а также 2 сюжетных демо уровня. Эти данные включены в Docker-образ; файлы Excel или дамп базы данных для них не нужны. При повторном запуске материалы не дублируются.

## 4. Открыть игру

Откройте [http://localhost:5173](http://localhost:5173) и зарегистрируйте учётную запись. При регистрации укажите логин, почту, отображаемое имя и пароль. Войти можно по логину или почте.

Для входа в редактор используйте логин `admin` и пароль из `ADMIN_BOOTSTRAP_PASSWORD`. После входа откройте раздел «Администратор». Если аккаунт уже существовал, повторный запуск контейнеров не меняет его пароль.

В разделе «Тренировки» выберите готовый метод или принцип либо создайте новый. Укажите порядок в каталоге, тему знаний и персонажа, затем добавьте ситуации, сцены, ответы и итоговые результаты. Сохраните черновик и опубликуйте его. Изменения импортированной тренировки, сохранённые в редакторе, сохранятся при повторном запуске контейнеров.

Если меняли `FRONTEND_PORT`, подставьте новый порт в адрес. Документация API доступна по адресу [http://localhost:8000/docs](http://localhost:8000/docs), проверка сервера — [http://localhost:8000/health/ready](http://localhost:8000/health/ready) (с учётом `BACKEND_PORT`).

## Подключить модель для сюжетных разговоров

По умолчанию в `.env` указано `AI_PROVIDER=mock`: приложение запускается без ключа, а пошаговые и короткие тренировки работают с подготовленными ответами. Для разговоров с моделью в сюжете и собственном диалоге нужен ключ сервиса Cloud.ru Foundation Models.

Создайте ключ доступа к Foundation Models в кабинете Cloud.ru по [инструкции провайдера](https://cloud.ru/docs/foundation-models/ug/topics/api-ref__authentication). Сохраните выданный `Key Secret` и укажите в **локальном** `.env`:

~~~dotenv
AI_PROVIDER=compatible
AI_BASE_URL=https://foundation-models.api.cloud.ru/v1
AI_API_KEY=<ваш Key Secret>
AI_MODEL=ai-sage/GigaChat3.5-432B-A28B
AI_TIMEOUT_SECONDS=30
~~~

Замените `<ваш Key Secret>` самим ключом без угловых скобок. Затем примените настройки:

~~~sh
docker compose up -d --force-recreate backend cleanup
~~~

Ключ указывайте только в `.env`, не в браузере и не в файлах интерфейса. Запросы к модели тарифицируются Cloud.ru; оценка расхода приведена в [описании AI](docs/llm_architecture.md#расход-токенов-на-сессию). Тренировки модель не вызывают.

После завершения сюжетного или собственного диалога модель готовит краткий разбор с цитатами из реплик игрока и советами на следующий разговор. Это дополнительный запрос к модели; готовый разбор сохраняется и при повторном открытии не создаётся заново. В демо-режиме без ключа разбор ИИ недоступен.

## Развернуть на Vercel

В корне репозитория находится `vercel.json`: он собирает интерфейс и FastAPI как два сервиса одного проекта. После подключения репозитория в Vercel укажите корень проекта как корень репозитория. Публичный `/api/*` направлен к FastAPI, остальные страницы — к интерфейсу. Для прямого открытия страниц игры предусмотрен переход на `index.html` внутри сервиса интерфейса.

База из Docker Compose **не переносится** на Vercel автоматически. Подключите доступный из Vercel PostgreSQL и задайте в настройках проекта `POSTGRES_HOST`, `POSTGRES_PORT`, `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, а также `AUTH_SECRET_KEY`. Для разговоров с моделью добавьте `AI_PROVIDER=compatible`, `AI_BASE_URL`, `AI_API_KEY` и `AI_MODEL` по разделу выше. Секреты не записывайте в `vercel.json` и не задавайте `API_PROXY_TARGET` для облачной сборки.

До первого запуска игры примените миграции к этой базе (`alembic upgrade head`) и загрузите материалы командами `python -m app.admin.import_editorial --apply` и `python -m app.admin.seed_demo --apply` из папки `backend` с теми же переменными окружения. Если нужен стандартный администратор, задайте также `ADMIN_BOOTSTRAP_PASSWORD` и выполните `python -m app.admin.bootstrap --login admin --email admin@admin.ru --display-name admin --if-missing`. В Vercel эти подготовительные команды не запускаются автоматически.

В локальном Docker браузер обращается к API через прокси Vite. На Vercel запросы браузера идут через публичный маршрут `/api/*`; внутреннее service binding между интерфейсом и бэкендом для этого не требуется.

## Обновить установленный проект

Перед обновлением создайте резервную копию базы данных по инструкции ниже. Затем из папки проекта выполните:

~~~sh
git pull --ff-only
docker compose up --build -d
docker compose ps -a
~~~

Обновление применяет миграции и загружает актуальные материалы. Данные в постоянном томе PostgreSQL сохраняются. Если `git pull --ff-only` сообщает о локальных изменениях или расходящихся ветках, сначала разберитесь с ними: команда не должна перезаписывать ваши файлы.

## Сохранить базу данных

При стандартных значениях `POSTGRES_USER=arena` и `POSTGRES_DB=arena`:

~~~sh
docker compose exec db pg_dump -U arena -d arena -Fc -f /tmp/arena-backup.dump
docker compose cp db:/tmp/arena-backup.dump ./arena-backup.dump
~~~

Файл `arena-backup.dump` появится в папке проекта. Если меняли имя пользователя или базы в `.env`, замените `arena` в командах. Сохраните файл в закрытом месте: дамп содержит учётные записи и игровые данные. Повторное выполнение команды с тем же именем заменит предыдущую копию.

## Остановить и снова запустить

~~~sh
docker compose stop
docker compose start
~~~

Для удаления контейнеров с сохранением базы выполните `docker compose down`. Следующий запуск — `docker compose up -d`. **Не добавляйте `-v` к `docker compose down`, если хотите сохранить базу данных:** этот флаг удаляет тома Docker.

## Если возникла ошибка

| Что произошло | Что проверить |
|---|---|
| Docker недоступен | Запустите Docker Desktop или Docker Engine; `docker version` должен показывать `Server`. |
| Порт уже занят | Измените нужный `FRONTEND_PORT`, `BACKEND_PORT` или `DB_PORT` в `.env` и повторите запуск. |
| Один из подготовительных контейнеров завершился с ошибкой | Посмотрите `docker compose logs --tail=100 migrate content-import demo-seed admin-bootstrap`. |
| Сервер или интерфейс не готов | Посмотрите `docker compose ps -a` и `docker compose logs --tail=100 backend frontend db`. |
| После смены `POSTGRES_PASSWORD` база не принимает пароль | Существующий том PostgreSQL сохраняет прежний пароль. Верните прежнее значение в `.env` или отдельно измените пароль в самой базе; том не удаляйте. |
| Разговор с моделью не работает | Проверьте `AI_PROVIDER`, адрес, ключ и название модели в `.env`, затем пересоздайте backend командой из раздела о подключении модели. |
