# Архитектура frontend

Актуально на 29 сентября 2026 года. Приложение написано на React, TypeScript и Vite. Запуск через Docker Compose описан в [README](../README.md).

## Страницы

| Путь | Назначение |
|---|---|
| `/` | Выбор независимых режимов |
| `/training` | Методы и принципы в редакционном порядке |
| `/training/custom` | Настройки своего диалога |
| `/training/mission/:id` | Подготовка тренировки и запуск сессии |
| `/training/guided/:id` | Пошаговая тренировка |
| `/training/branching/:id` | Сценарий выбранного метода или принципа |
| `/story` и страницы миссий | Сюжетная карта и подготовка разговора |
| `/session/:id` | Свободный разговор в виде визуальной новеллы |
| `/knowledge` | Материалы и самопроверка |
| `/characters` | Карточки персонажей и PAEI |
| `/account` | Личные данные, разговоры, статистика |
| `/admin` | Редактор, доступный роли `admin` |

Точные маршруты определены в `frontend/src/App.tsx`. Все серверные вызовы и типы ответов сосредоточены в `frontend/src/api.ts`.

## Состояние и данные

- `App.tsx` хранит состояние входа. JWT хранится в `sessionStorage` браузера; при выходе отправляется `POST /api/v1/auth/logout`, затем локальная копия удаляется. После перезагрузки пользователь проверяется запросом `GET /api/v1/users/me`.
- Каталоги берутся с backend, а не из локального массива. Экраны различают загрузку, пустой список и ошибку.
- `GameSession.tsx` ведёт свободный разговор через WebSocket и загружает сохранённые реплики из API. `GuidedTraining.tsx` и `BranchingTraining.tsx` работают через REST и подготовленные графы без AI.
- `NovelStage.tsx` показывает говорящего и текст постепенно. Новая начатая реплика получает фокус, но уже загруженные окна пользователь перелистывает сам.
- `Admin.tsx` позволяет создавать ветки, сюжетные миссии, персонажей, материалы, короткие и пошаговые тренировки. Пошаговый редактор задаёт ситуации, три ответа, разбор, подсказку повторной попытки и финальную самопроверку.

## Адаптивность и изображения

Стили находятся в `frontend/src` и связанных файлах CSS. Изображения лежат в `frontend/public/images`; их назначение описано в [README иллюстраций](../frontend/public/images/README.md). При добавлении нового экрана проверьте ширину телефона, отсутствие горизонтального скролла, размер полей ввода и доступность кнопок в сцене.

## Проверка изменений

```sh
docker compose exec frontend npm run build
docker compose exec frontend npm test
```

Сборка запускает проверку типов TypeScript. Основные UI-проверки лежат рядом с компонентами в `frontend/src/*.test.tsx`.
