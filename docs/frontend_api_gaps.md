# Связь экранов и API

Актуально на 29 сентября 2026 года. Точные типы клиентских запросов находятся в `frontend/src/api.ts`, серверные маршруты — в `backend/app`. Swagger доступен локально по `http://localhost:8000/docs`.

| Экран | Основной контракт |
|---|---|
| Вход, регистрация, выход | `POST /api/v1/auth/register`, `/login`, `/logout`; `GET /api/v1/users/me` |
| Кабинет | `PATCH /api/v1/users/me`, `GET /api/v1/users/me/stats`, `GET /api/v1/sessions` |
| Каталоги | `GET /api/v1/missions`, `/storylines`, `/knowledge`, а также детали и список персонажей |
| Сюжет | `GET /api/v1/storylines/{id}/progress`, брифинг и `POST /api/v1/sessions` |
| Свой диалог | `POST /api/v1/sessions` с `custom_context` |
| Свободный ход | `WS /api/v1/ws/sessions/{id}` и `GET /api/v1/sessions/{id}/messages` |
| Пошаговая тренировка | `GET /api/v1/sessions/{id}/guided`, `POST .../guided/choice`, `POST .../guided/answer` |
| База знаний | Список, детали, отметка прочтения, тест, сохранение попытки |
| Админка | `GET /api/v1/admin/overview`, создание и изменение материалов и их статуса |

Сюжетная миссия открывает следующую после успешного результата движка. Ручное завершение разговора успех не засчитывает. JWT отзывается при выходе; повторное использование отвергают и REST, и WebSocket. Визуальная новелла получает публичный текст и эмоцию, а оценка и скрытый контекст остаются на backend.

## Ограничения, которые требуют отдельного решения

1. В сюжетной сессии сейчас один основной `character_id`. Для полноценного разговора нескольких персонажей понадобятся связь миссии с несколькими героями и `speaker_id` в сообщениях.
2. Редактирование внешности игрока отложено; используется фиксированный персонаж без лица.
3. `neutral`, `warm`, `tense`, `angry` — технические эмоциональные кадры. Финальные изображения персонажей ещё можно заменить без изменения API.
4. Точный расход токенов AI не сохраняется; см. [оценку и метод измерения](llm_architecture.md#расход-токенов-на-сессию).
