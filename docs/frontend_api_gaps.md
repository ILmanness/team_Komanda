# Фронтенд и API игрового MVP

## Подключено

| Экран | API |
| --- | --- |
| Вход и регистрация | `POST /api/v1/auth/login`, `POST /api/v1/auth/register`, `GET /api/v1/users/me` |
| Кабинет | `PATCH /api/v1/users/me`, `GET /api/v1/users/me/stats`, `GET /api/v1/sessions` |
| Каталоги | `GET /api/v1/missions`, `GET /api/v1/storylines`, `GET /api/v1/storylines/{id}`, `GET /api/v1/knowledge`, `GET /api/v1/knowledge/{id}` |
| Карта сюжета | `GET /api/v1/storylines/{id}/progress` и серверная проверка доступа при создании сессии |
| Подготовка миссии | `GET /api/v1/missions/{id}/briefing`, `GET /api/v1/game/options` |
| Свой диалог и миссии | `POST /api/v1/sessions`, `GET /api/v1/sessions/{id}`, `GET /api/v1/sessions/{id}/messages`, `POST /api/v1/sessions/{id}/finish` |
| Игровые ходы | `WS /api/v1/ws/sessions/{id}` с `player.message` или `player.choice` |
| Наполнение | Защищённый редактор `/admin` для сюжетных линий, миссий, тренировок, вариантов и подсказок |

Ручное завершение возвращает `final_result.result=failure`. Только успешное завершение движком записывает `story_mission_progress` и открывает следующую миссию в той же ветке. Эта запись сохраняется после удаления истории разговоров. Визуальная новелла берёт эмоцию из `session_messages.payload.emotion`; старые реплики показываются с нейтральной эмоцией. В режиме `AI_PROVIDER=mock` ответы заготовлены, а оценка строится на простых демонстрационных правилах.

Брифинг отдаёт публичные сведения о миссии. Полный `GET /api/v1/missions/{id}` может содержать скрытые настройки движка и на игровых экранах не используется. История сессий доступна только владельцу.

## Что ещё согласовать и реализовать

1. **Несколько персонажей в сюжетной сцене.** Текущие `missions.character_id` и `game_sessions.character_id` описывают одного собеседника. Для нескольких героев нужны связь миссии с персонажами и идентификатор говорящего в каждой реплике. Изображения и эмоциональные варианты персонажей пользователь предоставит позже; сейчас используется временный силуэт.
2. **Параметры своего диалога.** Поля свободного `custom_context` нужно согласовать с окончательным контрактом нового движка. Текущая форма остаётся временной.
3. **Оценка эмоций.** Текущие `neutral`, `warm`, `tense`, `angry` выводятся из игровой оценки. Для актёрской подачи потребуется отдельный контракт эмоции и изображения от генератора реплик.
4. **Прогресс знаний и тесты.** Если функции войдут в MVP, потребуются отметки прочтения и API вопросов/попыток. Сейчас интерфейс показывает материалы без фиктивного процента.
