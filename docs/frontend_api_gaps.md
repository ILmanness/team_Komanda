# Фронтенд и API после подключения игрового движка

## Подключено

| Экран | API |
| --- | --- |
| Вход и регистрация | `POST /api/v1/auth/login`, `POST /api/v1/auth/register`, `GET /api/v1/users/me` |
| Каталоги | `GET /api/v1/missions`, `GET /api/v1/storylines`, `GET /api/v1/storylines/{id}`, `GET /api/v1/knowledge`, `GET /api/v1/knowledge/{id}` |
| Подготовка миссии | `GET /api/v1/missions/{id}/briefing`, `GET /api/v1/game/options` |
| Свой диалог и миссии | `POST /api/v1/sessions`, `GET /api/v1/sessions`, `GET /api/v1/sessions/{id}`, `GET /api/v1/sessions/{id}/messages`, `POST /api/v1/sessions/{id}/finish` |
| Игровые ходы | `WS /api/v1/ws/sessions/{id}` с событием `player.message` и ключом идемпотентности |

Брифинг отдаёт только публичные сведения о миссии. Полный `GET /api/v1/missions/{id}` может содержать скрытые настройки движка и на игровых экранах не используется. История сессий доступна только владельцу. В режиме `AI_PROVIDER=mock` интерфейс помечает ответ и оценку как демонстрационные.

## Что ещё нужно

1. **Контент для запуска.** В локальной базе пока нет опубликованных миссий, сюжетных линий и материалов. Нужны хотя бы одна тренировочная и одна сюжетная миссия с назначенным персонажем, PAEI-профилем и профилем сложности. Публичный endpoint редактирования контента для этого не нужен.
2. **Несколько персонажей в сюжете.** Сейчас `missions.character_id` и `game_sessions.character_id` поддерживают одного собеседника. Для сцен с несколькими героями нужны связь миссии с персонажами, `speaker_id` в видимой истории и событии ответа, а также порядок появления.
3. **Выбор вариантов.** Движок принимает текстовый `player.message`; для миссий `single_choice` нужен публичный список вариантов и ход с `choice_id`, без передачи скрытых правил оценки.
4. **Прогресс сюжета.** Нужен `GET /api/v1/storylines/{id}/progress` или поля доступных и пройденных этапов в ответе сюжетной линии. Сейчас карта показывает структуру миссий.
5. **Прогресс знаний и тесты.** Если эти функции войдут в MVP, потребуются отметки прочтения и API вопросов/попыток. Пока интерфейс показывает материалы без фиктивного процента.

Форма собственного диалога сейчас отправляет свободный `custom_context`: ситуацию, роли, цель, манеру собеседника и лимит реплик. Состав полей следует согласовать с окончательным контрактом нового движка.
