# Архитектура backend

Актуально на 29 сентября 2026 года. Backend — FastAPI на Python 3.12, асинхронное подключение к PostgreSQL через SQLAlchemy/psycopg и миграции Alembic. Локальный запуск описан в [README](../README.md).

## Пакеты

| Путь | Ответственность |
|---|---|
| `backend/app/main.py` | Создание приложения, подключение маршрутов, healthcheck |
| `backend/app/config.py` | Настройки из переменных окружения и адрес БД |
| `backend/app/db.py` | Асинхронный пул соединений |
| `backend/app/auth` | Регистрация, вход, JWT, проверка роли и отзыв при выходе |
| `backend/app/catalog` | Публичные сюжетные линии, миссии, персонажи, знания |
| `backend/app/users` | Кабинет и статистика пользователя |
| `backend/app/sessions` | Создание сессий, история, WebSocket и REST пошаговых тренировок |
| `backend/app/game` | Оценка, игровой state, память, цель, подсказки и ход |
| `backend/app/ai.py` | Интерфейс модели, mock и совместимый `/chat/completions` клиент |
| `backend/app/admin` | Проверяемый редактор, импорт и начальное наполнение |
| `backend/app/retention.py` | Очистка старых данных |

## Авторизация

После входа backend выдаёт JWT с обычным сроком 480 минут. Каждый выпуск имеет уникальный `jti`. Выход записывает SHA-256 отпечаток токена в `revoked_access_tokens` до его срока истечения; сам токен в БД не сохраняется. HTTP и WebSocket проверяют отзыв, а браузер удаляет свою копию из `sessionStorage`. Записи об истёкших токенах удаляет `cleanup`.

Роль `admin` проверяется сервером в `backend/app/admin/router.py`. Новый пользователь получает роль `player`. Администратора создаёт bootstrap только при отсутствии аккаунта; пароль берётся из локального `.env`.

## Ход свободного диалога

1. WebSocket принимает реплику с ключом идемпотентности; сервер сохраняет её как ожидающую.
2. Context Builder собирает снимок миссии, персонажа, правил, памяти и ограниченной истории.
3. Evaluator запрашивает структурированную оценку (или использует локальное правило для особых реплик), проверяет цитаты и отдаёт событие движку.
4. Движок обновляет состояние; AI Opponent создаёт реплику персонажа. После проверки ответа GoalTracker при необходимости отдельно проверяет достижение цели.
5. Состояние, сообщения, память и результат сохраняются транзакционно. Повтор того же ключа не должен применять ход второй раз.

Обычный свободный ход может сделать до трёх запросов к модели. Тренировки работают по подготовленным вариантам и не вызывают AI. Разбор потребления см. в [AI-документе](llm_architecture.md#расход-токенов-на-сессию).

## Редактор и данные

Администратор создаёт ветки, миссии, персонажей, знания и тренировки. Пошаговый сценарий редактора собирается в граф узлов `guided_training`; ответы, разборы, повтор и финальная самопроверка находятся в сохранённой конфигурации миссии. [Как устроен контент](content_and_admin_design.md). Миграции до `0011` и сроки хранения описаны в [архитектуре данных](data_architecture.md).

## Проверки

```sh
docker compose exec backend pytest -q
docker compose exec -e RUN_DB_TESTS=1 backend pytest -q
docker compose exec backend ruff check app tests migrations
docker compose exec backend alembic current
```

DB-тесты создают отдельную временную схему. Проверка `/health/ready` подтверждает доступность БД и базовых таблиц, но не делает платный запрос к модели.
На текущем снимке `ruff` сообщает о накопленных замечаниях; эта команда включена для просмотра состояния стиля и не требуется для запуска приложения.
